# Interface Writing

Write from the user's side of the screen.

- Name things by what people recognize and control, not by implementation
  details.
- Prefer specific plain verbs. Controls should describe the resulting action.
- Keep an action's name consistent through the flow.
- Let each element do one job: labels label, examples demonstrate, and help
  text explains.
- Errors state what happened and the next useful action.
- Empty states explain what the surface is for and offer a relevant next step.
- Use sentence case and match the product's established voice.

Preserve factual claims supplied by the product. Do not invent metrics,
capabilities, customer outcomes, or roadmap status to make copy sound stronger.
